# План: создание бота-ассистента для Max (промты для ИИ-агентов)

## Цель
Не писать код бота сейчас, а подготовить **6 промт-файлов в корне репозитория**, которые пользователь по очереди будет запускать в кодинг-агенте (Cursor/Claude Code) для пошагового дописывания кода бота в тот же репозиторий. Каждый промт — самостоятельный, указывает на уже созданные в предыдущих шагах файлы и результат, который должен получить.

## Контекст (изучен из документации Max и SDK)

### Решения, принятые с пользователем
- **6 шагов** — 6 отдельных md-файлов в **корне репозитория** (`C:\Work\Projects\bot-max-assistant\`).
- **Max API**: используем официальный TypeScript-SDK `@maxhub/max-bot-api` (Bot, ctx.reply, фильтры, готовые типы `Update`/`Message`/`Attachment`). НЕ пишем свою REST-обёртку с нуля.
- **Rate limiter**: токен-бакет 30 rps (глобально) + задержка ≥500ms между отправками в один `chat_id` (лимит Max: 2 msg/sec per-чат).

### Ключевые факты документации Max (фиксируем в промтах, чтобы агент не выдумывал поля)
- Домен: `platform-api2.max.ru`. Авторизация: заголовок `Authorization: <token>` (передача через query-параметры НЕ поддерживается). Токен из `BOT_TOKEN`.
- **Webhook требования**: HTTPS на порту 443, валидный TLS-сертификат доверенного ЦС (самоподписанные НЕ поддерживаются), ответ HTTP 200 в течение 30 сек, иначе MAX повторяет до 10 раз с экспоненциальным ростом; через 8 часов неуспеха — авто-отписка.
- **Подписка**: `POST /subscriptions` с телом `{ url, update_types: ["message_created","bot_started"], secret }`. Секрет приходит в заголовке `X-Max-Bot-Api-Secret` каждого вебхук-запроса — проверять на сервере.
- **Лимит текста сообщения**: 4000 символов (поле `text` в `NewMessageBody`). Саммари при превышении разбиваем на несколько сообщений.
- **Лимиты скорости**: 30 rps глобально, **2 сообщения/сек в один чат/диалог/канал**.
- **Update** (`message_created`): `{ update_type, timestamp, message: Message }`.
- **Message**: `{ sender?, recipient: {chat_id, chat_type}, timestamp, link?: {type:'reply'|'forward', message: MessageBody}, body: {mid, seq, text, attachments} }`.
  - `chat_id` берём из `message.recipient.chat_id`.
  -(reply-цель: `message.link?.type === 'reply'` → текст в `message.link.message.body.text`.
- **AudioAttachment** (голосовое): `{ type: 'audio', payload: { url, token } }`. **`payload.url` — прямая ссылка для скачивания файла**, отдельный метод API не нужен — качаем `fetch(payload.url)`. ⚠️ У AudioAttachment **НЕТ поля `duration`** (оно есть только у VideoAttachment).
  - **Длительность для решения «>30 сек»** определяем на стороне бота: парсим загруженный аудиофайл (muteiconv/ffprobe через `music-metadata` npm-пакет, без внешних бинарников) либо закладываем fallback — считать по размеру/типу. В промте шага 3: использовать npm-пакет `music-metadata` для чтения длительности из буфера; если не удаётся — всегда прогонять саммари (conservative).
- **Команды бота** регистрируются через `PATCH /me/commands` (есть `bot.api.setMyCommands`). Полезно для `/translate`, `/summary`.
- **Форматирование**: `format: 'markdown'` или `'html'` в `NewMessageBody`. В промтах: ответы бота форматировать markdown (короткие абзацы, эмодзи), БЕЗ таблиц (требование системного промпта).
- **`X-Max-Bot-Api-Secret`**: в `.env.example` добавить `WEBHOOK_SECRET`. На сервере сравнивать `req.get('X-Max-Bot-Api-Secret')` с `config.webhookSecret`; при mismatch — `401` без обработки.
- `package.json` шага 1: dependencies `@maxhub/max-bot-api`, `express`, `better-sqlite3`, `@anthropic-ai/sdk`, `dotenv`, `music-metadata`; devDeps `typescript`, `tsx`, `@types/express`, `@types/better-sqlite3`, `@types/node`. Скрипты: `dev` (tsx watch), `build` (tsc), `start` (node dist), `subscribe` (tsx scripts/subscribe.ts).

## Сценарии/edge-cases, которые нужно отразить в промтах
- **Шаг 1**: (а) Приход Update с неизвестным `update_type` → логировать и `200 OK` (не падать); (б) `X-Max-Bot-Api-Secret` не совпадает → `401` без обработки; (в) webhook приходит на путь кроме `/webhook` → `404`; (г) `bot_started` → `maxClient.sendMessage(chat_id, "Привет! ...")`.
- **Шаг 2**: (а) SQLite файл не существует → создать и прогнать миграцию при старте; (б) Anthropic/Whisper 429/5xx → retry с экспоненциальным backoff, до 3 попыток, затем throw → ловится в хендлере; (в) пустой текст сообщения не сохраняем в БД.
- **Шаг 3**: (а) `attachments` нет или нет `audio` → не наш кейс,(chunk return; (б) `payload.url` пустой → логировать ошибку, ответить в чат «Не удалось получить голосовое сообщение»; (в) Whisper вернул пустую транскрипцию → «Не удалось распознать речь»; (г) не удалось прочитать длительность → default: пропустить саммари (или всегда прогонять — уточнено в промте: conservative = всегда прогонять саммари, надёжнее).
- **Шаг 4**: (а) сообщение не reply → игнор; (б) reply-исходник без текста (только вложение) → ответить «Нет текста для перевода»; (в) исходник уже на русском → всё равно «перевести» определяется моделью → если уже русский, ответить原文 + заметку.
- **Шаг 5**: (а) `/summary` без аргумента → default последние 50 сообщений; (б) `/summary 24h` → парсим период, берём все сообщения за период; (в) сообщений <5 → ответить «Слишком мало сообщений для саммари»; (г) samрии >4000 → разбить по границам абзацев, отправить несколько сообщений последовательно через rate limiter; (д) саммари пустой → «Не удалось составить саммари».
- **Шаг 6**: (а) одна ошибка в хендлере не валит обработку следующих Update; (б) `setMyCommands` вызывается один раз при старте; (в) README описывает сертификат Минцифры как опцию.

## Риски / открытые вопросы
- **Длительность аудио без `duration` в схеме**: решили через npm `music-metadata`. В промте 3 — fallback conservative (всегда саммари), если чтение длительности не удалось.
- **Whisper формат файла**: Max отдаёт аудио в mp3/wav/m4a — Whisper API принимает эти форматы; отправляем multipart `file` с правильным `filename` и `mimeType`.
- **Туннель для HTTPS**: в README шага 6 указываем `ngrok http 3000` / `cloudflared tunnel` + что WEBHOOK_URL должен быть `https://...` и команда `npm run subscribe` регистрирует подписку.
- **Rollout**: каждый шаг коммитим отдельно (агент оставляет uncommitted; пользователь решает про коммит). Валидация на каждом шаге: `npx tsc --noEmit`.
- Если точки ниже вне scope — отметить: graceful разбивка длинных саммари — в scope; логирование в файл/logrotate — **out of scope** (только console.log); обработка `message_edited`/`message_removed` — **out of scope** (не требуется по ТЗ).
