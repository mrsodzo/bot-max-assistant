## Схема объектов Max (релевантно для этого шага)
- **Message**: `{ sender?, recipient: { chat_id, chat_type }, timestamp, body: { mid, seq, text, attachments } }`.
- `chat_id` → из `message.recipient.chat_id`.
- Текст сообщения (команда): `message.body.text`.
- **Лимит текста одного сообщения Max: 4000 символов**. Если саммари длиннее — разбить на несколько сообщений.

## Триггер и аргументы
Команда: `/summary` с **опциональным** аргументом:
- `/summary` (без аргумента) → последние 50 сообщений (дефолт).
- `/summary 50` → последние N сообщений (N — целое, `1 ≤ N ≤ 500`; если вне диапазона — Clamp до диапазона с логированием).
- `/summary 24h` → все сообщения за последние 24 часа (с текущего момента минус период, где `h` = часы, `m` = минуты, `d` = дни). Поддерживаемые суффиксы: `h`, `m`, `d` (минимум `1m`, максимум `7d`). Также поддержка `/summary 24h30m` (комбинировать допускается, но необязательно — минимум один суффикс).
- Нераспознанный аргумент → дефолт последние 50 сообщений + логировать «нераспознанный аргумент, взял дефолт».

## Что нужно создать в этом шаге

### `src/handlers/summary.ts`
Экспортируй `async function handleSummary(message: Message): Promise<boolean>` (возвращает `true`, если сообщение было командой `/summary` и обработано; `false` — если не команда). Тип `Message` импортируй из `@maxhub/max-bot-api` или локального файла типов шага 1.

Логика:
1. **Проверка команды**: `const t = (message.body.text ?? '').trim().toLowerCase()`. Если не `t === '/summary'` и не `t.startsWith('/summary ')` → `return false`.
2. **Парсинг аргумента**: `const arg = t.slice('/summary'.length).trim()`. Реализуй функцию парсинга:
   - пустой → count=50, режим count.
   - число → count=N (с clamp 1..500), режим count.
   - период (`24h`, `30m`, `2d`, `1d6h` и т.п.) → `sinceMs = Date.now() - минуты/часы/дни`, режим period.
   - нераспознано → count=50 режим count + логировать.
3. **Выборка из БД** через `src/db.ts`:
   - режим count → `db.getMessagesByCount(chatId, count)`.
   - режим period → `db.getMessagesByPeriod(chatId, sinceMs)`.
   - Вернёт массив `{ sender_id?, sender_name?, text, timestamp }` в порядке **возрастания времени** (для саммари хронологически).
4. **Edge: мало сообщений**: если `messages.length < 5` → отправить «Слишком мало сообщений для саммари» → `return true`.
5. **Sophisticate user prompt** для `llm.summarizeChat`: отформатировать массив в текст «`[sender_name, ISO-время]: text` …». Если `sender_name` пустой — `«участник {sender_id}»`.
6. **Anthropic-саммари**: `llm.summarizeChat(messages)` из `src/llm.ts` (там системный промпт + инструкция «структурированно по темам, в конце отдельный блок явных договорённостей»).
7. **Разбивка по 4000 символов**: реализуй `splitForMax(text, limit = 4000)` — разбивать по **границам абзацев** (`\n\n`), при необходимости по строкам (`\n`), последний кусок может быть короче. Не рвать слово посередине без необходимости. Если один абзац длиннее лимита — рвать по предложению (`.`/`!`/`?`) либо по лимиту с `…`.
8. **Отправка**: для каждого куска — `maxClient.sendMessage(chatId, part, { format: 'markdown' })`. Rate limiter шага 1 гарантирует соблюдение лимитов Max. Отправлять **последовательно** (await каждый), чтобы порядок сохранялся.
9. Логировать количество сообщений в выборке и количество частей ответа.
10. `return true`.

## Edge-cases (реализуй)
- (а) `/summary` без аргумента → последние 50 сообщений.
- (б) `/summary 24h` → парсим период, берём все сообщения с `timestamp >= sinceMs` из БД.
- (в) Сообщений < 5 → «Слишком мало сообщений для саммари», `return true`.
- (г) Саммари > 4000 символов → разбить по абзацам, отправить несколько сообщений последовательно через `maxClient.sendMessage` (rate limiter).
- (д) `llm.summarizeChat` вернул пустую/пробельную строку → «Не удалось составить саммари», `return true`.
- (е) Ошибка БД при выборке → логировать, ответить «Не удалось получить историю сообщений», `return true`.
- (ж) Ошибка Anthropic (после retry из шага 2) → логировать, ответить «Не удалось составить саммари», `return true`.
- (з) N слишком велико (>500) или мало (<1) → clamp до диапазона, логировать.
